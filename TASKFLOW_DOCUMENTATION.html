1. Application Overview

TaskFlow is a comprehensive project and task management application designed for team collaboration. It features a spreadsheet-style UI for task management, milestones tracking, daily POA (Plan of Action), work done logging, analytics dashboard, AI chatbot, and full role-based access control.

Key Capabilities

Spreadsheet inline editing | Milestones | POA & Work Done | Recurring Tasks | Nested AND/OR Filters | Multi-sort | Pagination | Column Resize/Freeze/Show-Hide | Mobile Card UI | Project-User Mapping | Role-Based Access Control | Groq AI Chatbot | Analytics Dashboard | Completion % Hierarchy | Color-coded Fields | Auto Actual Dates | Subtask Validation | Task Edit Log

Row Level Security (RLS)

All tables have RLS enabled. Policies allow authenticated users to SELECT all data and INSERT/UPDATE/DELETE with appropriate checks. Project-level filtering is handled at the application layer via the useAccessControl hook.

  • Multi-level sort (ascending/descending on any field)

  • Color-coded fields (status, priority, assignee, department, project)
  • Overdue highlighting (red background, overdue days badge)
  • Completion % based on subtask status weights
  • CSV export
  • Daily POA and Work Done buttons

6. Access Control & Roles

Roles

RoleAccess Level
AdminFull access to everything. All projects, all data, settings, user management.
ManagerAssigned projects only. Can bulk update. Can manage milestones.
Team LeaderAssigned projects only. Standard task operations.
Team MemberAssigned projects only. Limited by role_permissions table.

Access Control Flow

1. User logs in → profiles.id = auth.users.id
2. useAccessControl() hook:
   a. Looks up master_members by matching profiles.email (case-insensitive)
   b. Gets member's role (admin/manager/team_leader/team_member)
   c. Queries project_members to get user's assigned project IDs
   d. Returns: { isAdmin, memberId, userProjectIds, projectMembers }
3. If admin → userProjectIds = null (sees all)
4. If non-admin → userProjectIds = [list of assigned project IDs]
5. Every page filters: tasks, milestones, POA, filter dropdowns, create forms

7. API & Data Flow

Authentication Flow

Login: supabase.auth.signInWithPassword({ email, password })
Signup: supabase.auth.signUp({ email, password, options: { data: { full_name } } })
Magic Link Invite: supabase.auth.signInWithOtp({ email, options: { emailRedirectTo, shouldCreateUser: true } })
Password Reset: supabase.auth.resetPasswordForEmail(email)
Logout: supabase.auth.signOut()

On signup → DB trigger creates profiles row → AuthContext fetches profile

Data Fetching Pattern

All data fetching uses TanStack React Query:
- queryKey: unique cache key (e.g., ['all-tasks'], ['projects'])
- queryFn: async function calling supabase.from(table).select(...)
- Automatic cache invalidation after mutations
- Stale-while-revalidate for smooth UX

Example:
const { data: tasks = [] } = useQuery({
  queryKey: ['all-tasks'],
  queryFn: async () => {
    const { data } = await supabase.from('tasks').select('*').order('created_at', { ascending: false });
    return (data || []) as Task[];
  }
});

Mutation Pattern

Task Create: useCreateTask() hook → supabase.from('tasks').insert(...)
Task Update: supabase.from('tasks').update({ field: value }).eq('id', taskId)
Task Delete: supabase.from('tasks').delete().eq('id', taskId)

After each mutation:
  queryClient.invalidateQueries({ queryKey: ['all-tasks'] })
  → React Query refetches → UI updates automatically

Completion % Algorithm

Status completion_weight values:
  YTI (Yet to Initiate) = 0
  WIP = 0.5
  PMO Review = 0.5
  Client Pending = 0.5
  ERP Pending = 0.5
  Hold = 0.5
  Done = 1
  Dropped = 1
  Future = 1

Task % = If has subtasks: average(subtask weights) * 100
         If no subtasks: own status weight * 100
Milestone % = average(linked task weights) * 100
Department % = average(milestone %)
Project % = average(department %)

13. Key Design Decisions

DecisionRationale
Spreadsheet UI over popupsUser explicitly requested inline editing, no dialogs for task editing
Departments open (not locked to projects)One department can be used across multiple projects
Milestones project-level only (no dept)One milestone can cut across different departments in a project
Groq over GeminiGemini free tier had quota=0 without billing; Groq works free
Recurring via DB trigger (not cron)Auto-creates next task when status changes to closed/done
POA once per day per userUnique constraint on (user_id, submitted_date)
Access control at app layerMore flexible than RLS for complex multi-table filtering
Single page app with Vercel rewritesReact Router handles all routing client-side
